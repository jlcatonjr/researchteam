Patch release. Still pins agentteams v1.1.4 (b82d78e7). Small hardening of the autosync workflow from v1.1.8 and clearer messages (#205). The job that opens the autosync PR now requires the gate's commit id to be a full 40 hex characters, and counts changed file names exactly, so a name ending in line breaks is also treated as sensitive. The gate step reads the `force` input from `env:`. `researchteam workflow-sync` with no answer on standard input now says that nothing was written and names `--yes`. `scripts/check_toolchain.py` names the interpreter that cannot import researchteam and says to use the project environment. **Rule for every repository that runs autosync** (`docs/agentteams-update-policy.md`): a workflow that holds a write token or a secret restores no cache, and neither does a read-only one whose result gates a merge, a release or a publication; the read-only gate job can still write Actions caches. Derived repos move with `researchteam update --ref v1.1.9`, then `python3 scripts/check_toolchain.py --write-lock --tag researchteam=v1.1.9 --tag agentteams=v1.1.4`, then `researchteam workflow-sync` (add `--yes` where there is no terminal) with the repository's own `@security` review.
