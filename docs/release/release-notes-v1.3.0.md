First release of the researchteam 1.3 line. It pins agentteams v1.3.0 (536306d2) and is v1.3.0-rc.1 plus the release files, install instructions that name v1.3.0 (with a test that guards them) and one wording correction. Nothing that runs in a derived repository differs from the candidate.

- **agentteams 1.3.** `toolchain.lock` and the `update` / `research` extras move from agentteams v1.2.1 to v1.3.0, and the agent team is regenerated. An overwrite render now stops before any write when it would drop agents the orchestrator routes to, unless they are named with `--accept-routing-loss`; a file-bound clearance is refused by an unretracted HALT in the repository's other team logs. agentteams 1.3.0 needs Python 3.11 or later; researchteam itself still supports 3.10.
- **Term index: a pinned copy of agentteams' core.** `scripts/term-index-core/` holds the two core modules of the signed agentteams v1.3.0 as exact bytes, with a manifest; the engine is reduced to adapters. The copy is checked against its manifest before it runs and needs no installed agentteams; CI compares the copy with the signed tag. Do not edit it: a changed byte stops `term-check`, `term-build` and `validate`, and `researchteam doctor` reports a failure. Generated indexes, findings and exit codes are unchanged, except that a linked or oversized `terms.json` is refused with one combined message and a symlinked `terminology/index/` reads as stale.
- **Survey toolkit: the contract is version 1.** `docs/survey-toolkit.md` is frozen, and its per-study sign-off log is specified against agentteams 1.3.0's gates-only team directory. No survey tool ships yet; the tools are planned for the next minor release.
- **Concept map.** `templates/concept-map/` and `scripts/build_concept_map.py`: a reusable, interactive map of a debate, with its protocol and a skill.
- **Bibliography explorer contract 1.1:** three optional evidence columns.
- **Derived autosync workflow:** the release-locked check fetches the tag shallowly. A repository receives it through `researchteam update --workflow` and its own review.
- **Install instructions** name v1.3.0 (they named v1.0.2 in every release from 1.1.1 to 1.2.1), and a test now keeps them on the newest stable release.
- **Governance.** The toolchain-group file is re-signed for this repository alone; the term-index core, its loader and the engine are paths whose pull requests need a `@security` PASS; merged pull-request heads may be deleted automatically.

**Moving a derived repository.** Install the new researchteam first, because an older one does not sync the term-index core: verify the signed tags researchteam `v1.3.0` and agentteams `v1.3.0`, install `researchteam[update]` at the commit the researchteam tag peels to (the extra installs agentteams v1.3.0; Python 3.11 or later; a workspace with signed decision rows or a toolchain-group file also needs agentteams' `signing` extra there, or the group file does not verify), then `researchteam update --ref v1.3.0` and `python3 scripts/check_toolchain.py --write-lock --tag researchteam=v1.3.0 --tag agentteams=v1.3.0`. A locked repository leaves two release lines at once (researchteam 1.2 and agentteams 1.2), and `check_toolchain.py` refuses a cross-line `--tag` for each pin, so drop both the `researchteam.tag=` and the `agentteams.tag=` line from `toolchain.lock` first. Both line moves are trust changes and get the repository's own `@security` review.

`release/1.2` stays open for v1.2.N backports and keeps agentteams 1.2. Policy: `docs/release-policy.md`, "The 1.3 line". Full list and the upgrade notes: `CHANGELOG.md`.
