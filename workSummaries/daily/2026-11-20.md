Plan: `references/plans/verify-tag-shallow-fetch.plan.md`.

- **Report.** A fleet session reported that `check_toolchain.py --write-lock` from researchteam v1.2.0 timed out
  in several derived repositories. `researchteam/_release.py` `verify_tag` fetched the tag with the repository's
  full history under a 300-second limit. The operator chose in the session picker that this session fixes it

  never fetches full history. Every check after the fetch is unchanged. Three new tests pin the fetch arguments,
  the retry and the double failure.

  session's docs PRs (#223 to #226), so the merge commit's tree differs from the head's; its diff against its
  first parent is exactly the PR's six files. Tests are green on `main` at `01c353b`.
