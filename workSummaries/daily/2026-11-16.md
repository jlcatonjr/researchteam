Changes in both `.github/workflows/agentteams-sync.yml` and `researchteam/scaffold/agentteams-sync-derived.yml`:

- **Permissions.** Nothing is granted at workflow level (`permissions: {}`). The #172 evergreen-PR lookup moved
  into its own job, `evergreen_pr`, which has `contents: read` and `pull-requests: read` only and passes `open`
  to the `autosync` job as a job output. `autosync` keeps its write access, waits for `evergreen_pr`
  (`needs`), and still runs if the lookup fails (`if: !cancelled()`).
- **The lookup's answer.** Only a numeric count is accepted. An empty or non-numeric result leaves `open` unset,
  which the gate treats as unknown, falling back to the current branch's ref. This came from `@security`'s first
  review.
- **Checkout credentials.** `actions/checkout` now runs with `persist-credentials: false`, so the write token is
  not left in `.git/config` while the gate runs integrated code.
  - create-pull-request v6.1.0 (`c5a78066`) sets up its own credentials from its `token` input. This was checked
    in its `src/git-config-helper.ts` at that commit.
  - The separate evergreen fetch step was removed, because `fetch-depth: 0` already fetches that branch.
- **Gate script.** The comments in `scripts/agentteams_autosync_gate.sh` now name the `evergreen_pr` job. This
  came from `@code-hygiene`.
- **Test and changelog.** `test_workflows_look_up_the_pr_in_a_read_only_job` was added, along with a CHANGELOG
  Unreleased entry. Derived repos get the scaffold only at `init`, so an existing repo copies it itself.
