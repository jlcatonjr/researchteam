# v1.0.2 (planned as v1.0.1): bootstrap installs agentteams[signing] (finding from Batallion's v1.0.0 sync)

Source: batallion-1f, 2026-10-19. scripts/bootstrap_toolchain.sh (layer-2 managed) installs agentteams without
the `signing` extra, so every Ed25519 gate check in a derived repo's .venv fails closed ("requires the 'signing'
extra (cryptography)").

Fix (lands on main first; backport to release/1.0 for v1.0.1 per docs/release-policy.md):
1. Bootstrap installs `agentteams[signing]` (pinned and --local) under the S-10 constraints for the signing
   chain (cryptography==50.0.0, cffi==2.1.1, pycparser==3.0). Derived repos don't receive docs/release/, so
   the pins are embedded in the script; a test keeps them equal to docs/release/constraints-2026-10-16.txt.
2. Bootstrap fails loudly when cryptography still can't be imported.
3. Tests in tests/test_toolchain.py.

Follow-ups (separate PRs): CLAUDE.md managed block (unconditional layer-1 wording; link to docs/release-policy.md
which derived repos don't get); AGENTS.md codex_write_policy block read by Grok is an agentteams render issue,
to report upstream.
