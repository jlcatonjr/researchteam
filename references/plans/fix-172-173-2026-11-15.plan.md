# Fix researchteam #172 and #173 (2026-11-15)

as #172 and #173. Operator ruling through the interactive selection interface in session researchteam-59:
"Fix both now".

## #172: the autosync gate trusts a stranded evergreen branch

`scripts/agentteams_autosync_gate.sh` takes its baseline from `origin/chore/agentteams-autosync` whenever that
branch exists. After a failed PR step, or a PR closed without merging, a re-run reports "nothing to integrate"
and no PR is ever opened.

Fix: use the evergreen branch's ref only when an open PR has that branch as its head (`gh pr list`). With no
open PR, take the baseline from the current branch, so the update is detected again and `create-pull-request`
opens a PR from the existing branch. If the PR lookup cannot run, warn and use the current branch: that errs
toward detecting the change, never toward stranding it. Both workflows (`.github/workflows/agentteams-sync.yml`
and `researchteam/scaffold/agentteams-sync-derived.yml`) pass `GH_TOKEN` and `GH_REPO` to the gate step, and the
gate test harness gets a `gh` stub. The workflow change needs a `@security` PASS naming the path (PS-2).

## #173: `update` can replace an unfenced CLAUDE.md wholesale

`_reconcile_fenced` keeps an unfenced, divergent file under `--yes`, but interactively, approving writes the
whole upstream file over it, with a diff preview cut at 50 lines.

Fix: the interactive path appends the fenced managed block below the unchanged content, as `researchteam adopt`
already does. It never replaces the file. `--yes` keeps the file unchanged, as now.
