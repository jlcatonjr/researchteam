# Audit findings — term register and synced term index (2026-11-16)

This file records, finding by finding, the two rounds of review behind
`term-index-2026-11-16.design.md`: the audit of the draft plan, and the review of the first implementation
(commit 761c938). Each finding has the reviewer's identifier, a one-line statement and its disposition.
The design's sections 0 and 0a give the resolutions in prose. The audit of the research project is a
separate record, `Projects/CodedTermIndexing/04-adversarial-conflict-audit.md`.

Dispositions: **done** (resolved as the reviewer asked, or equivalently), **changed** (resolved another
way, stated), **deferred** (not in this change, with the reason), **declined** (with the reason).

### 1.3 `@security` — CONDITIONAL PASS, 18 conditions

1. Root from the script's location or `RT_ROOT` after realpath; the payload's `cwd` unused.
2. Only `tool_input.file_path` and `notebook_path` read; stdin capped; NUL, CR or LF in the path ignored.
3. The path's realpath must lie inside a project under `Projects/`; the same rule for command-line arguments.
4. The payload path selects the project only and is never read or written.
5. Symbolic links refused for the project directory, `terminology/`, the register and the outputs.
6. Writes by `mkstemp` in the same directory, then `os.replace`.
7. Glossary escaping and labelling; no matched document text in the glossary; relative paths only.
8. `re.escape` on every form; no expression supplied by the register.
9. Size limits as defects; absolute and `..` patterns refused; walks do not follow links; id slug enforced.
10. The hook's message: fixed prefix, codes, identifiers and positions only, about 2 KB; other failures exit 0.
11. The check writes nothing, bytecode included; no network, child process, `eval`, `exec`, `pickle` or `yaml`.
12. `validate` treats exit 1 and 2 as failures and ignores the advisory switch; advisory mode is announced.
13. An example file only; nothing writes `.claude/settings*.json`; quoted command, a timeout, a comment on running outside the sandbox and on removal.
14. `term-init` never overwrites; nothing modifies the register or the documents.
15. The pre-commit snippet stays in documentation, check-only, with no `git add`.
16. Tests for each of the above.
17. A scan of the new files for credentials, personal data and machine paths.
18. A `@security` PASS naming the paths before a PS-2 merge.

All were implemented. Their verification is in part 2.1.
