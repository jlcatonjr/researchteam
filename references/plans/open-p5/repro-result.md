**Verdict: not reproduced.** Running researchteam from source (main = v1.1.4 plus docs) with the pinned
agentteams 1.1.3 left a frozen root `AGENTS.md` byte-identical in every case tried. The baseAgent
history points to another cause (see "What baseAgent's history shows").

(agentteams 1.1.3), `PYTHONPATH=~/githubrepositories/researchteam`. The runs used a scratch directory

## Every writer of the root AGENTS.md during `update`, and whether it is guarded

`run_update` (`researchteam/_update_cmd.py:629-634`) wraps the whole body in `_guarded` (`:611-619`).
`_frozen_begin` (`:543-574`) snapshots AGENTS.md (`:571`) before any write. `_frozen_end` (`:577-603`, in a
`finally`) restores those bytes (`:590-594`) and fails closed if any frozen path still differs.

| Writer | Where | Inside `_guarded` | Frozen-codex behaviour |
|---|---|---|---|
| Layer-2 managed-file sync | `_run_update_body` `:303-430`, files from `_manifest.py` | yes | AGENTS.md is not a managed file; `_is_frozen` skip at `:315` as well |
| Notes sync | `_sync_notes` `:645+` | yes | does not target AGENTS.md; `_is_frozen` skip at `:691` |
| Layer 1, copilot-vscode `agentteams --update --merge` | `_run_agentteams` `:1105+` | yes | agentteams `drop_frozen` (`agentteams/cli/generate.py:634`) |
| Layer 1, native claude/goose (`--materialize-native`) | `_render_native_surfaces` `:1068+` | yes | goose emits `../../AGENTS.md`; agentteams 1.1.3 drops it ("skipped (a frozen surface owns it: codex)"), and refuses an unfenced one anyway |
| Codex refresh | `_refresh_codex_unless_frozen` `:1224` | yes | skipped: `_codex_allowed` turns codex off (`:622-626`) |
| Bridge merges (`--bridge-merge`) | `_merge_bridges` `:463-516` | yes | all skipped when AGENTS.md is frozen (`:474-480`) |
| `init` template extraction | `_init_cmd.py` | n/a (init only) | not on the update path |

Other checks:
- **Which file sets the freeze:** `_frozen.load` (`_frozen.py:54-73`) reads only **brief.json**.
  `.researchteam` and git HEAD (`recorded`, `at_head`, `:119-148`) only feed the "was frozen" check.
  A `.researchteam`-only freeze therefore refuses the run as an unverified unfreeze; it is never silently ignored.
- **`--ref`:** only selects the upstream template that `fetch_raw` reads from (`cli.py:190-209`). It is resolved
  before `_guarded`, but the guard reads the local brief.json and `.researchteam` from `root`, never the
  template. Layer 2 never syncs `brief.json` or `.researchteam`, so neither an older nor a newer template
  changes the frozen set.
- The guard code is unchanged from v1.0.1 through v1.1.4 (`write_bytes(agents_md)` at `:593` in each tag).

## What the downstream repository's history shows (read-only; it is private, so details are summarized)

- On its main branch, codex is frozen, and the committed AGENTS.md is clean. That file was already a Goose bridge
  AGENTS.md before the freeze, so the "full Goose AGENTS.md" is already the committed content there.
- The last commit that rewrote AGENTS.md is a CI autosync commit on its autosync branch. On that branch's line, the
  repository had deliberately unfrozen codex, by its own recorded decision. With codex unfrozen, rewriting
  AGENTS.md is the intended behaviour.
- Its toolchain lock pins an older researchteam 1.0.x, which has the same guard. A local run there would not use
  v1.1.4.

The likeliest explanation: the overwrite was seen on a branch or checkout whose brief.json no longer
freezes codex (its unfrozen line), and was then attributed to a frozen-codex `update --ref v1.1.4`.

## Residual gaps (not the reported bug)

1. **Restore is in-process only.** `_frozen_end` runs from a `finally`. A SIGKILL or a harness timeout that kills
   the process leaves an unfrozen render's AGENTS.md write in place. That needs agentteams' own `drop_frozen` to be
   missing (an older agentteams without its own frozen filter) or bypassed. An atomic-rename snapshot file
   (e.g. `.git/researchteam-frozen-AGENTS.md`), restored at the next `_frozen_begin`, would close it.
2. **`python -m researchteam.cli` silently does nothing.** `cli.py` has no `if __name__ == "__main__": main()` and
   there is no `researchteam/__main__.py`, so a `python -m` invocation exits 0 having run nothing. The script
   calls `main()` directly instead. **Fixed in the P5 PR:** `researchteam/__main__.py`, a `__main__` guard in
   `cli.py`, and `tests/test_module_entry.py`.
